# Data provenance

RippleGate ships with a reproducible, versioned evaluation dataset prepared for
testing. This page states exactly where every kind of data in the system comes
from so a reviewer never mistakes example records for production traffic.

## What is evaluation data

| Artifact | Origin |
|---|---|
| `examples/orders-api/openapi-*.json` | Versioned compatibility fixtures authored for the contract-diff engine |
| `examples/orders-api/server.js` | Reference producer service built for consumer test execution |
| `examples/billing-service/`, `examples/reporting-service/` | Reference consumer services with executable contract suites |
| `db/migrations/003_demo_data.sql` | Preconfigured evaluation domain (organization, services, policy v1, two registered dependencies) |
| Analysis runs, findings, assessments in a local database | Generated by the engine when the walkthrough scripts execute |

None of these are actual customer integrations, production traffic, or records
from a live deployment. No personal data, credentials, or confidential material
of any kind is included. The fixture identity model enforces this structurally:
fixture-sourced contract versions carry a `FIXTURE` source type and a fixture
fingerprint, and the schema rejects a fixture row that claims a git commit SHA
(`db/migrations/001_core.sql`).

## Where provenance surfaces in the product

- The web dashboard labels fixture-sourced analyses as "Fixture fingerprint"
  rather than "GitHub commit".
- Reports include the source identity and digests of the exact inputs analyzed
  (`services/api/app/reporting/report.py`).
- `docs/TESTING.md` and `docs/LIMITATIONS.md` state the scope of executed
  consumer coverage: the two registered reference consumers.

## Why this matters

Compatibility analysis is only as trustworthy as its evidence chain. By keeping
the evaluation dataset explicit, versioned, and structurally distinguished from
GitHub-sourced contracts, RippleGate demonstrates the provenance discipline a
real deployment would require of customer data.
